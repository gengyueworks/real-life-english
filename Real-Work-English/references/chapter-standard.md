# 章节制作与自检标准

## 目录

1. 固定结构

## 一、固定结构

每章只保留四个主体板块：

1. 真实背景
2. 可以直接跟读的完整英文对话
3. 三轮模拟加压
4. Opinion Presentation Practice

末尾可以保留简短来源说明。不增加独立单词表、知识科普或无稿会议演练。

## 二、事实与模拟

统一使用：

- `【真实业务事实】`：材料中可以确认的信息。
- `【真实原话】`：逐字稿中确实出现的表达。
- `【整理英文】`：根据真实场景整理、简化或翻译的表达。
- `【模拟训练】`：为练习设计的回应、分歧和条件。
- `【待确认信息】`：材料不足或需要内部确认的信息。
- `【场景候选】`：根据岗位推测、等待用户确认的场景。

客户立场不能从内部讨论中推断。模拟回答不能写成已经发生的事实。来源冲突、数字不清或说话人不明时，必须标注。

写对话前核对：

1. 会议对象。
2. 当前业务阶段。
3. 会议真正要推进的事项。
4. 用户可以决定、推动和需要确认的事项。

业务准确度优先于结构完整。真实业务中的未知、冲突和不透明信息可以保留，不能为了顺畅自动补全。

## 三、完整会议对话

### 篇幅和难度

- 主对话控制在750至850词。
- 正常跟读约5至7分钟。
- 每个角色单次发言尽量控制在1至4个短句。
- 每章新增3至5个高频专业词汇或商务表达。
- 初级用户使用更短句、更常见动词和更清楚的话轮，不减少真实业务逻辑。
- 删除重复背景、重复复述和可以放进会后邮件的执行清单。

### 开场

会议场景安排两至三轮简短small talk。话题可以来自天气、节日、出差、近期项目或对方刚分享的信息。用户也需要回应并分享相关信息，形成一来一回。

不同章节尽量更换话题。small talk应能自然连接当章议题。

### 连续讨论

完整对话不能写成采访提纲。重要议题优先按照以下节奏推进：

1. 用户提出判断或建议。
2. 对方回应、补充条件或提出分歧。
3. 用户复述或确认重点。
4. 双方继续一至两轮，讨论顾虑、条件或执行方式。
5. 用户确认阶段性结论或待确认事项。

连续两个纯提问后，必须加入观点、复述、解释或方案。对方回答可以不完整、带条件、回避承诺或需要内部确认。

每章选择三至五个沟通功能，例如聚焦议题、邀请补充、澄清观点、暂时搁置支线、切换议题和确认共识。

## 四、金字塔表达

用户的重要发言默认采用：

1. 明确结论。
2. 两到三个直接相关的事实或理由。
3. 对业务结果的影响。
4. 建议、条件、问题或下一步。

每次发言只表达一个中心观点。

### 表达判断

结论、依据、业务影响、邀请回应。

### 提出方案

建议、原因、所需条件、下一步。

### 追问信息

当前判断、缺少的信息、需要它的原因、一个明确问题。

### 总结会议

只确认讨论结束，并说明会后发送follow-up。不要口头逐项念完整行动清单。

金字塔结构主要存在于逻辑中。不要反复使用`My main point is`或`There are three reasons`等前缀。能直接表达观点时，直接说观点。

一句话连续并列的名词、条件或事项不能超过4个。信息过多时保留最重要的2至3项，剩余内容拆句或放进会后材料。

## 五、商务冲突

完整对话中约20%至30%的内容需要出现有事实基础的冲突、分歧、不透明信息或条件交换。

冲突可以来自：

- 双方目标或优先级不同
- 对投入、资源和责任的预期不同
- 对时间、范围和质量的判断不同
- 对价格、库存、渠道或结果存在不同理解
- 客户要求超出用户权限
- 关键信息尚未确认

冲突必须来自用户材料，或由真实条件推导出的合理模拟。不能为了戏剧性制造客户立场。

### 默认异议结构

1. 肯定合理部分。
2. 明确判断。
3. 提供具体事实。
4. 解释潜在影响。
5. 提出折中方案。
6. 确认。

### 直接型和强硬型

根据用户确认的风格调整语气。可以减少缓冲、提前表达底线或拒绝不合理要求，但必须保留：

- 事实依据
- 利益或风险
- 权限边界
- 交换条件或可接受方案
- 对方需要确认的下一步

强硬不能变成攻击、情绪宣泄或虚假威胁。

## 六、三轮模拟加压

三轮训练必须来自当章真实议题。每轮包含：

1. 一个具体冲突。
2. 用户需要完成的沟通动作。
3. 可折叠的参考回答或三至五轮参考对话。
4. 三条本轮可复用表达。

参考回答遵循用户确认的冲突风格，同时保持事实、影响、方案和下一步。

每条可复用表达包括：

- 英文句型
- 逻辑功能
- 当章业务例句

优先提炼顺序、条件、因果、影响、分阶段、职责划分和调整机制。

## 七、Opinion Presentation Practice

每章设置一个与当章真实经历直接相关的问题，目标表达时长约90秒。问题可以模拟业务面试官对这段经历的追问，但不能变成脱离经历的通用面试题。

练习包含：

1. 一个明确的英文问题。
2. 简短的中文业务背景。
3. 中文思考路径。
4. 三至五个英文关键词或短语。
5. 可折叠的英文参考表达。
6. 四条本轮可复用表达。

参考表达按照问题类型组织：

- 策略题：总体目标、关键判断、执行分工、衡量方式、调整机制。
- 复盘题：当时目标、实际问题、个人判断、推动动作、后续学习。
- 冲突题：双方诉求、关键事实、业务影响、处理方案、结果或待确认事项。
- 汇报题：结论、证据、风险、需要支持、下一步。

参考表达必须有清晰逻辑，同时保持自然口语和用户当前岗位视角。

## 八、四层自检

### L1 事实

- 每个业务判断能否找到材料依据。
- 推测是否标记为候选或模拟。
- 客户立场是否被误写成事实。
- 不透明和待确认事项是否保留。
- 是否虚构数字、承诺或结果。
- 会议对象、业务阶段和权限是否准确。
- 匿名化后是否保留业务逻辑。

### L2 商务逻辑

- 用户是否带着观点进入讨论。
- 重要发言是否符合金字塔结构。
- 对话是否回应上一轮信息。
- 冲突是否来自真实利益、资源、权限或信息差。
- 异议处理是否符合用户确认的风格。
- 直接或强硬表达是否仍有事实、风险、条件和下一步。
- 用户是否做出超出权限的承诺。

### L3 英文口语

- 英文是否简单、直接并适合当前水平。
- 是否有复杂长句和高级词汇堆积。
- 每句话是否尽量只承担一个功能。
- 是否反复使用结构前缀形成口水话。
- 单句是否连续并列超过4项。
- 新增专业表达是否控制在3至5个。
- 语气是否符合用户确认的沟通风格。

### L4 学习体验

- 主对话是否为750至850词。
- 是否有两至三轮简短small talk。
- 三轮模拟是否对应真实冲突。
- 观点练习是否直接来自当章经历。
- 是否包含完整的练习提示和参考表达。
- 章节是否循序渐进。
- 总章节是否为四至八章。
- 是否避免一次索取或生成过多内容。
